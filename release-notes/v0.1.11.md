# AutoRE-CLI v0.1.11

The CLI and Agent Skill both advance to 0.1.11. Five platform binaries are
compiled locally from source revision
`b7379a2f2267fe4471373a7bfa4b113122ed1395` with pinned Rust/Cargo 1.97.1
and the existing locked dependencies. Download the matching archive and verify its digest
against `SHA256SUMS.release` before installing.

## Changes

- `describe --format json` exposes bounded command metadata without reading a
  target. `--diagnostic-format json` opts into typed, bounded stderr errors.
- Eight commands can emit explicit `kinds-v1` result roots. Their default
  `legacy` outputs remain available; the paired Skill admits exact supported
  kind/version combinations and rejects unknown or contradictory roots.
- The Skill audits the 0.1.11 CLI argument contract for request identity and
  duplicate no-progress detection. The artifact reader adds hash-bound,
  bounded object-key and Unicode string views.
- The source engine also includes conservative static evidence refinements for
  selected typed operands, value flow, and language/protection records. These
  do not establish complete source recovery or runtime behavior.
- English and Chinese READMEs now explain these interfaces and show the
  static-analysis workflow in a new diagram.

## Install and acceptance

Each platform archive contains one CLI binary, the Agent Skill, offline
installers, checksums, provenance and notices. Verify the extracted archive
with `./verify.sh` (or `py -3 scripts/autore_distribution.py verify` on
Windows) before installation. Rerun the installer to upgrade a managed 0.1.10
installation. An existing installation does not change when this Release is
published.

The release acceptance checks the full source workspace and feature matrix,
public offline tests, deterministic archive rebuilds, a native Linux x86-64
CLI probe, and an isolated 0.1.10 → 0.1.11 install/upgrade/rollback matrix.
macOS ARM64/x86-64, Linux ARM64 and Windows x86-64 receive cross-build and
static format checks on this Linux host, not native runtime certification.
macOS binaries are ad-hoc signed with verified code-page hashes; they are not
Developer ID signed or notarized. Windows is unsigned, with static LLVM-MinGW
runtime linkage and a zero PE timestamp. No target binaries or target-derived
artifacts are executed during release validation.
No real-agent/model task evaluation or cross-host runtime test is claimed.
